# restaurant-order

## 概要

店名「米至上主義」の飲食店注文システム。

お客さんは席の QR コードをスマホで読み込んで注文ページを開く。店名が表示されたあと、テーブル番号と、年齢層・性別を選ぶと注文を始められる。メニューはカテゴリごとのページに分かれ、写真付きで 2 列に並び、選んだ年齢層・性別に合う商品はオレンジの枠と「おすすめ」の札で示される。商品を選ぶと、トッピングや付け合わせ、米の種類、米の量を順に選び、商品が「かご」に入る。かごを開くと注文内容の確認画面が表示され、そこから注文を確定できる。

## 起動方法

### お客さん（スマホ）で使う場合

1. 下の QR コードをスマホのカメラで読み込む
2. ブラウザが開き、店名「米至上主義」が表示される
3. 「ご注文をはじめる」を押し、テーブル番号（1〜20）を入力して「注文を始める」を押す
4. 年齢層と性別を選んで「メニューを見る」を押す

![注文ページを開く QR コード](qr.png)

QR コードが読めない場合は、次の URL を直接開く。
https://kdt26aie40011-source.github.io/resutaurant-order/

### 公開の準備（作成者が一度だけ行う）

1. GitHub のリポジトリを開き、Settings → Pages を開く
2. Branch を `main`、フォルダを `/ (root)` にして Save を押す
3. 数分後に https://kdt26aie40011-source.github.io/resutaurant-order/ で開けることを確かめる
4. この URL から QR コード画像を作り、`qr.png` としてリポジトリに入れる

### パソコンで確かめる場合

```
git clone https://github.com/kdt26aie40011-source/resutaurant-order.git
cd resutaurant-order
```

フォルダ内の `index.html` をダブルクリックしてブラウザで開く。インストールは不要。

## システム構成

### 使用した技術

HTML / CSS / JavaScript（ライブラリなし）、データ保存には localStorage を使用。公開には GitHub Pages を使用。

### ファイル構成

| ファイル | 役割 |

| images/ | 商品写真を入れるフォルダ。noimage.svg は写真が読み込めないときの代わりの画像 |

| CLAUDE.md | 開発を任せる AI 向けの指示書 |
| README.md | この説明書 |

## データ設計

### 保存方法

お店とのデータのやりとりは、すべて `js/api.js` を通して行う。

| データ | 送るタイミング | 送り方 |
| --- | --- | --- |
| 注文（商品・おしぼり・お水） | かご画面で「注文を確定する」を押したとき | まとめてお店へ送信 |
| 店員呼び出し | 「呼ぶ」を押したとき | すぐにお店へ送信 |
| 会計 | 注文履歴で「会計する」を押したとき | お店へ送信 |
| 注文履歴 | 注文履歴を開いたとき | お店からこのテーブルの注文を取得 |

現在は試作段階で、お店側の受け取り先（サーバー）はまだ存在しない。そのため、`api.js` の送り先 `STORE_API_URL` を空にしてあり、空のあいだは次のように動く（試作モード）。

- 送信：送るはずのデータを localStorage の `kome.outbox` に記録し、送信成功として扱う
- 取得：`kome.outbox` に記録した注文のうち、同じテーブル番号のものを返す

受け取り先ができたら、`STORE_API_URL` に URL を設定するだけで、実際に送信するように切り替わる。かごの中身・テーブル番号・選んだアレルギー物質は、再読み込みで消えないよう localStorage に保存する。

### データの形

| データ | 項目 |
| --- | --- |
| メニュー | id, name, price, emoji, category, image, needsRice, toppingIds, standardSideIds, allergens, recommended, placeholder, tags |
| 付け合わせ | id, name, price（単品価格。つけあわせページと定食で共通）, emoji, allergens, recommended, placeholder, tags |
| トッピング | id, name, price, allergens |
| 米の種類 | id, name, extraPrice |
| 米の量 | id, label, grams, extraPrice |
| アレルギー物質 | id（egg / milk / wheat / shrimp / crab / walnut / buckwheat / peanut）, label |
| 設定 | storeName, tableMin, tableMax, quantityMin, quantityMax, sideSurcharge, callCooldownSec, personalPerCategory |
| タグ | id（kids / hearty / light / healthy / fish / meat / fried / sweet / traditional）, label |
| 年齢層 | id（preschool / elementary / teen / age20 / age40 / age60）, label, weights（タグごとの点数） |
| 性別 | id（male / female / none）, label, weights（タグごとの点数） |
| 来店情報 | tableNumber, startedAt, ageGroup, gender |
| かごの中身 | uid, kind（product / oshibori / water）, productId, toppingIds, sides（[{ sideId, price, isStandard }]）, riceTypeId, riceSizeId, quantity, unitPrice |
| 注文 | orderId, tableNumber, items, total, orderedAt, paid |
| 店員呼び出し | callId, tableNumber, calledAt |
| 送信記録（試作モード） | type（order / call / checkout）, data, sentAt |

## 画面と機能

### 画面構成

- **スタート画面**：店名「米至上主義」を中央に大きく縦に表示し、「ご注文をはじめる」ボタンを置く
- **テーブル番号入力画面**：番号の入力欄と「注文を始める」ボタン。番号を入れるまでメニューに進めない
- **お客さま情報入力画面**：年齢層（小学生未満・小学生・中高生・20〜39歳・40〜59歳・60歳以上）と性別（男性・女性・未回答）を選ぶ。両方選ぶまでメニューに進めない
- **メイン画面**：上部と下部は固定し、中央だけ縦にスクロールする

| 位置 | 部品 | 動き |
| --- | --- | --- |
| 左上 | 店名（小さく表示）とテーブル番号 | テーブル番号入力後は常に表示 |
| 右上 | 現在時刻 | 1 秒ごとに更新（時:分） |
| 中央上 | カテゴリボタン（定食・一品物・つけあわせ・ドリンク・デザート・お問い合わせ） | 横スクロールで移動でき、押すとそのページに切り替わる |
| 中央 | 各カテゴリの商品欄 | 写真付きの横 2 列で縦スクロール。定食は 10 行以上、その他は 5 行程度。写真・商品名・価格・アレルギー物質を表示 |
| 左下 | 現在の料金 | かごに入れた商品の合計金額 |
| 右下 | 「かごへ進む」ボタン | 押すと注文確認画面へ移動する |

- **商品の選択画面**：上部に写真、その右横に商品名・価格・アレルギー物質。その下にトッピング欄と付け合わせ欄があり、それぞれ枠内をスクロールして選ぶ。付け合わせ欄は、その定食の標準のものを上、それ以外を区切り線の下に割増価格で表示する。米を選ぶ商品は、続けて米の種類と量を選ぶ
- **注文確認画面（かご）**：かごの中身、数量変更、削除、合計金額、「注文を確定する」ボタン
- **お問い合わせページ**：おしぼり・お水（個数を選んでかごに入れる）、注文履歴、店員呼び出しの 4 つの欄
- **注文履歴**：このテーブルの注文を新しい順に表示し、これまでの合計と未会計の金額、「会計する」ボタンを表示する

### 要件と機能の対応

| No | 要件 | どの機能で満たしたか |
| --- | --- | --- |
| 1 | 店名表示 | 最初のスタート画面と、以降の全画面の左上に店名を表示 |
| 2 | メニュー表示 | カテゴリボタンでページを切り替え、各ページで商品を写真付きの横 2 列で縦スクロール表示（定食は 10 行以上、その他は 5 行程度） |
| 3 | 注文 | トッピング・付け合わせ → 米の種類 → 米の量の順に選んでかごに追加し、かご画面の「注文を確定する」で確定 |
| 4 | 注文データの記録 | 注文確定・店員呼び出し・会計で、データをお店へ送信する（試作モードでは localStorage の `kome.outbox` に記録）。注文履歴はお店から取得して表示する |
| 5 | おすすめ機能 | 選んだ年齢層・性別と商品のタグから点数を出し、各ページで点数の高い商品（最大 3 品）をオレンジの枠で囲み、写真の左上に「おすすめ」の札を付ける。選んだアレルギー物質を含む商品はおすすめしない。また、recommended が true の商品を各ページの「店長イチオシ」欄に表示し、写真の右上に「店長イチオシ」の札を付ける |
| 6 | 会計 | 注文履歴で、これまでの合計と未会計の金額を表示し、「会計する」で会計を送信して会計済みにする |
| 7 | 入力チェック | テーブル番号は 1〜20 の整数のみ。米の種類・量が未選択ならかごに追加できない。空のかごでは注文できない。数量、おしぼり・お水の個数は 1〜10 のみ。店員呼び出しは 30 秒間連続で押せない |
| 8 | アレルギー対応 | メニュー一覧・選択画面・かごで、写真と商品名と一緒にアレルギー物質を札で表示する。トッピングと付け合わせを合わせた物質も表示し、アレルギー選択欄で選んだ物質を含むものは赤く警告する |

### 自分で決めたこと

| 決めたこと | 理由 |
| --- | --- |
| 起動方法を QR コードにした | 実際の飲食店のように、席でスマホから注文できるようにするため |
| 公開に GitHub Pages を使った | 無料でサーバー不要、リポジトリをそのまま公開できるため |
| テーブル番号を入力しないと注文できないようにした | どの席の注文かを区別するため |
| テーブル番号は 1〜20 にした | 店の席数を 20 卓と想定したため |
| メニューをカテゴリごとのページに分けた | 商品数が多く、1 ページに並べるとスマホで探しにくいため |
| 定食だけ 10 行以上にし、その他は 5 行程度にした | 店のコンセプトが「米至上主義」で、米と一緒に食べる定食を主力商品にしたため |
| 店名・時刻・料金・かごボタンを固定表示にした | どのページにいても、合計金額の確認と注文確定ができるようにするため |
| 米を選ぶのは定食だけにした | ドリンクやデザートに米を選ばせるのは不自然なため |
| 米の種類と量を必須選択にした | 店のコンセプトが「米至上主義」で、定食を米なしで出すことはないため |
| 商品に写真を付けた | 文字だけより料理の内容や量がわかりやすく、選びやすいため |
| 写真がまだない商品は、絵文字から仮の写真を自動で描くようにした | 商品構想が決まる前でも、写真付きの画面を確かめられるようにするため |
| トッピングと付け合わせの欄を分け、それぞれ枠内でスクロールするようにした | 選択肢が多くても画面全体が長くならず、写真と商品名を見ながら選べるため |
| 付け合わせのデータを、つけあわせページと定食で共通にした | 同じ商品を二重に登録すると、価格やアレルゲンの修正漏れが起きるため |
| 標準以外の付け合わせも割増料金（一律 50 円）で選べるようにした | 選べる自由を残しつつ、定食ごとのおすすめの組み合わせに誘導するため |
| かごには、選んだ時点の価格を記録した | 後から価格を変えても、すでにかごに入っている注文の金額が変わらないようにするため |
| おしぼりとお水は、かごを経由して注文と一緒に送るようにした | 料理と一緒に届けられ、お店側の手間が減るため |
| 店員呼び出しは、かごを経由せずすぐに送るようにした | 急ぎの用件で、注文確定まで待たせられないため |
| 店員呼び出しは確認画面を出し、送信後 30 秒間は押せなくした | 押し間違いや連打で、同じ呼び出しが何度も届かないようにするため |
| 注文履歴は、お店から取得して表示するようにした | お店の記録を見せることで、お店と食い違いが起きないようにするため |
| 会計は注文履歴の画面で行うようにした | 注文の一覧と金額を見ながら会計できるようにするため |
| お店とのやりとりを api.js にまとめ、送り先がないあいだは試作モードにした | 受け取り先ができたときに 1 か所を直すだけで切り替えられ、今も何がいつ送られるかを確かめられるため |
| 送信に失敗したときは、かごの中身を残すようにした | 注文をもう一度入力し直さなくて済むようにするため |
| アレルギー物質は特定原材料 8 品目を基準にし、文字の札で表示した | 表示が義務付けられている品目で、記号の意味を覚えなくても読めるようにするため |
| アレルギー物質を含まない商品には [なし] と表示した | 空欄だと「含まない」のか「未記入」なのか区別できないため |
| 画面の下に混入の可能性についての注意書きを表示した | 表示がない商品でも、完全に含まないとは言い切れないため |
| 別のテーブル番号を入力したら、かごを空にするようにした | 前の席の注文が次の席に持ち越されないようにするため |
| テーブル番号のあとに年齢層と性別を選んでもらい、合う商品をおすすめするようにした | 商品が多くても、お客さまに合う商品をすぐ見つけられるようにするため |
| 年齢層は「小学生未満・小学生・中高生・20〜39歳・40〜59歳・60歳以上」にした | 区切りが重なると、どれを選べばよいか迷うため |
| 性別に「未回答」を用意した | 答えたくないお客さまも注文できるようにするため |
| おすすめは商品に付けたタグ（がっつり・あっさり・子ども向けなど）と、年齢層・性別ごとの点数で決めるようにした | 商品を追加しても、タグを付けるだけでおすすめに反映されるようにするため |
| お客さま向けのおすすめはオレンジの枠と左上の「おすすめ」、店のおすすめは右上の「店長イチオシ」と分けた | 2 種類のおすすめが同じ見た目だと、どちらの意味か区別できないため |
| 選んだアレルギー物質を含む商品は、お客さま向けのおすすめから外した | 食べられない商品をすすめないようにするため |
| メニューは仮のもので、開発は AI に任せ、AI 向けの指示書（CLAUDE.md）を置いた | 商品構想が決まっていない段階でも、ルールに沿って AI が仮の商品を追加・変更できるようにするため |
